Two defects found while surveying live state ahead of the LLM inference
replan. Neither has been touched — both are read-only observations, recorded
here so they survive until there's bandwidth to fix them.

## 1. beleriand has two default StorageClasses

```
$ kubectl get storageclass
NAME                     PROVISIONER                                     DEFAULT
aglarond-nfs (default)   cluster.local/nfs-subdir-external-provisioner   true
local-path (default)     rancher.io/local-path                          true
```

Both `aglarond-nfs` and `local-path` carry
`storageclass.kubernetes.io/is-default-class: true`. Kubernetes behavior when
two StorageClasses claim default status is undefined — a PVC that omits
`storageClassName` may bind to either, non-deterministically. In practice
this means a PVC intended for Aglarond (backed up, NFS, `ReadWriteMany`
capable) could silently land on `local-path` instead — node-local disk, no
backup, no RWX, and gone if the pod reschedules to a different node.

**Fix (Bucket B — needs a yes, mutates cluster state):**
```
kubectl patch storageclass local-path -p '{"metadata": {"annotations":{"storageclass.kubernetes.io/is-default-class":"false"}}}'
```
Non-destructive and reversible in one command, but it's a cluster mutation,
so it isn't applied without approval.

## 2. `learning-cluster` has no `.gitignore`, and the age private key is untracked in the repo root

```
$ cd ~/learning-cluster && git status --short
?? age.agekey
?? tls.key
?? tls.crt
```

`age.agekey` is the SOPS decryption key for that repo's secrets. It is
currently untracked, which means `git status` shows it — but there is no
`.gitignore` entry preventing a future `git add -A` (or `git add .`) from
staging and committing it. Since `learning-cluster` is the repo Flux actually
reconciles and pushes to GitHub, that would publish the private key publicly.

`tls.key` is in the same position — a private key sitting untracked with
nothing stopping it from being swept into a commit.

**Not fixed here.** This is a different, Flux-reconciled repo with its own
guardrails — it's listed in this project's Bucket C, not fixed as a side
effect of this replan. The fix, when done, is small: add a `.gitignore` with
`*.agekey` and `*.key` (mirroring what was just added to this repo), then
confirm neither file is already tracked in history (`git log --all --
age.agekey tls.key` — both came back empty in this check, so a plain
`.gitignore` addition is sufficient; no history rewrite needed).
